# Side Ask（旁路问答）

Snow App ESM 面板插件。在面板内用自己的输入框提旁路问题，**回答只流式显示在面板里**：
不回填输入框、不发送、不写入会话消息库。

- 插件 id：`com.seagull.side-ask`
- 面板 id：`main`
- 输入栏入口：模型选择器左侧，tooltip 为「打开旁路问答」

## 功能

| 能力 | 说明 |
| --- | --- |
| 旁路问答 | 面板内独立输入框，`Ctrl+Enter` 发送，回答流式渲染在面板内 |
| Markdown 渲染 | 回答按 Markdown 渲染（代码围栏、行内代码、标题、列表、引用、粗斜体、链接） |
| 不落库 | 请求不传 `conversationId`，native 不持久化本批消息 |
| 会话上下文 | 自动获取焦点会话消息作为参考（公开只读域，需 privacy 声明）；切换会话自动失效并重取 |
| 自有历史 | 对话数组存于插件私有存储 `app_plugin_values`，上限 200 条 |
| 进度报告 | 主会话任务进度报告：手动按钮随时生成，或主会话运行中按间隔自动生成（旁路，不写入会话历史）；可选系统通知 |
| 输入栏入口 | 点击后把输入框草稿带入面板并打开面板（不回填、不发送、不产生费用） |

## 会话上下文（全自动）

上下文不需要手动操作，只有一个开关：

| 行为 | 说明 |
| --- | --- |
| 默认开启 | `contextEnabled` 默认 `true`；可在设置或上下文栏关闭 |
| 提问时自动获取 | 若当前会话的上下文未载入或已失效，提问前自动拉取一次 |
| 会话切换自动失效 | 订阅 `runtime` 域，焦点会话变化即清空旧上下文并标记「已失效」，随后自动载入新会话 |
| 手动清除 | 上下文栏的「清除上下文」按钮（仅在已载入时出现） |
| 默认取全部 | 上下文轮数默认 `0` = 全部会话消息；设为 >0 才只取最近 N 轮 |
| 字符上限 | 默认 20000 字符，超出从头部截断，状态栏显示「已载入 X/Y 条」 |

### 为什么必须处理会话切换

旧实现只在用户点按钮时把上下文写进 state，之后不再变化。切换会话后旧上下文会**继续被送进新会话的提问**，导致答非所问。现在通过订阅 `runtime` 检测 `conversationId` 变化，先清空再重取，顺序固定（先清后取，避免旧内容泄漏到新会话）。

## Markdown 渲染

回答经内置轻量渲染器输出 React 元素，**不使用 `dangerouslySetInnerHTML`、不拼接 HTML 字符串**，因此没有 HTML 注入面：模型返回的 `<script>`、`<img onerror=...>` 等一律作为惰性文本显示。

支持：`` ``` `` / `~~~` 代码围栏（含语言标签）、行内代码、`#`–`######` 标题、有序/无序列表、`>` 引用、`---` 分隔线、`**粗体**`、`*斜体*`、`[文本](https://…)` 链接（仅 http/https，`javascript:` 不会被渲染为链接）。

流式期间未闭合的代码围栏按已闭合处理，避免逐字渲染时闪烁。用户自己的提问按纯文本显示（保留原始换行），只有助手回答走 Markdown。

## 工具调用标记清洗

旁路请求带 `disableTools: true`，但模型仍可能吐出**工具调用协议标记**——典型是 DeepSeek 的 `<｜｜DSML｜｜tool_calls>…`（`｜` 为全角 U+FF5C）。

**为什么会泄漏**：宿主只为 OpenAI / Anthropic / Gemini 的原生工具调用字段做解析，不认这些内联标记，于是标记作为普通文本落进 `content`，原文显示在面板里。这是宿主层面的解析缺口，不是上下文或输出长度限制。

**处理**：插件在展示层清洗（不动请求、不改协议）。`stripToolMarkers()` 覆盖：

| 形态 | 处理 |
| --- | --- |
| 成对标记 `<｜｜DSML｜｜tool_calls>…</｜｜DSML｜｜tool_calls>` | 整段删除（含中间内容） |
| 孤立开 / 闭标签 | 逐标签删除 |
| 悬空前缀（流式截断 / 漏写闭合） | 从标记处丢弃到文末 |
| 竖线变体 | 全角 `｜`、半角 `|`、制表符 `▁` 均识别 |
| 带属性标签 `<|invoke name="x">` | 一并匹配 |

接入 6 处：流式增量、最终文本、中止分支、失败分支、历史载入（顺带修复已存的脏数据）、历史渲染兜底。清洗只作用于助手回答，用户提问保持原样。

**不误伤**：普通 HTML 标签、`a | b` 竖线、Markdown 表格、代码块内的 `|` 均不受影响（专项用例覆盖）。

### 降低触发概率：系统提示词约束

默认系统提示词额外声明了本通道无工具可用，并明确禁止输出调用标记：

> 重要：本通道已关闭工具调用，你没有可用的工具，也拿不到文件、网络或命令输出。因此绝对不要尝试调用任何工具，不要输出 tool_calls、invoke、parameter、DSML 等调用标记或调用格式，也不要假装已经执行。所有内容都必须直接用自然语言回答；确实需要实际执行或读取才能回答时，直接说明你无法执行，并给出用户可自行执行的步骤。

这是**降低概率**，不是根治——模型仍可能不遵守，所以清洗逻辑必须保留为兜底。

**升级迁移**：`normalizeSettings` 优先保留已存配置（尊重自定义），因此仅改默认值对「已保存过设置」的用户不生效。插件把历史版本的默认文案列入 `LEGACY_DEFAULT_PROMPTS`：命中即视为「从未真正自定义」，自动升级到新默认值；不命中则原样保留，绝不覆盖用户自己写的提示词。

## 进度报告

「进度报告」是对**主会话当前任务**的进度总结——等价于在别的客户端用 `/btw 当前什么进度了 给我一份报告`，但走本插件的旁路通道：不打断主会话、不回填输入框、不写入会话历史（只存插件私有历史）。两种触发方式：

- **手动**：面板状态栏右侧的「进度报告」按钮。立即以最新焦点会话内容为上下文，让模型生成一份「已完成 / 进行中 / 待办 / 阻塞或风险」格式的报告，流式显示在面板里；
- **自动**：设置里开启「定时进度报告」（默认开）后，主会话运行中（`runtime.conversation.isStreaming`）每达到设定间隔（1–180 分钟，默认 10 分钟）自动生成一份。间隔从主会话本轮流式开始起算，主会话空闲时不触发。

细节：

- 进度报告**无条件携带最新会话上下文**（privacy scopes 已声明 `messages` / `conversations`），不受「自动携带会话上下文」开关影响——没有上下文的进度报告没有意义；没有可用上下文时会明确报错；
- 旁路通道正在生成时按钮禁用、自动触发跳过本轮，不会并发两个流；
- 报告请求在历史里带「进度报告」标记；
- 系统通知是**可选附加**（默认关）：仅自动生成的报告完成后，按「自动报告完成后发系统通知」开关额外走 `system.notify`（scope 为 `null`）。失败时面板如实显示原因。


## 问答通道（重要）

本插件通过宿主既有 IPC 通道提问：

```js
window.snow.createResponseStream(request, onChunk, onStreamId)
```

主进程 handler `chat:create-response-stream` 只做请求 normalize 与 native 调用，
**没有任何落库路径**。

### 不落库的关键约束

请求**绝不传 `conversationId`**。

宿主自身的三处调用都会传 `conversationId`，而 native 返回里带 `persistedUserMessageIds`
（落库回执）。宿主源码注释写得很直白：

```
// 增量消息：Rust 端按 conversationId 重建上下文并只持久化本批新消息。
```

传了 `conversationId` 就等于主动落库；省略它才是无状态补全。

### 非公开 API 风险

`createResponseStream` **不是宿主为插件设计的公开 API**。ESM 插件以 blob URL 在主窗口
渲染进程内 `import()`，而 preload 把完整的 `window.snow` 暴露在同一进程，因此技术上可调用。
这意味着：

- 越过宿主为插件设计的 `api.*` 边界，不受 `privacy.scopes` 约束；
- 宿主升级后签名或行为可能变化，插件可能失效；
- 面板内已明确提示这一风险，用户可选择「不再提示」。

运行时做能力探测（`createResponseStream` 与 `abortResponseStream` 必须同时存在），
缺失时显示明确提示，**不静默降级、不改用 `chatInput.sendMessage`**（那会落库）。

## 上下文来源

上下文走公开只读域：

```js
api.metadata.get(["messages", "conversations"], {})
```

- 整域敏感，已在 `plugin.json` 声明 `privacy.scopes: ["messages", "conversations"]`；
- 只读、live，与「不污染历史」不冲突；
- 只取 `role` 为 `user` / `assistant` 且 `content` 非空、`status !== "error"` 的消息；
- 按设置截取最近 N 轮（默认 3 轮），并按字符上限（默认 6000）从头部截断。

## 请求组装

```
messages = [
  { role: "system", content: systemPrompt (+ 可选上下文块) },
  ...插件自有历史（user / assistant）,
  { role: "user", content: 新问题 }
]
disableTools: true
```

`model` / `apiProfile` 留空时不传，由宿主按当前档案解析。

## 存储键（插件私有）

| 键 | 内容 |
| --- | --- |
| `sideAskHistory` | 问答历史数组，上限 200 条 |
| `sideAskSettings` | 设置（系统提示词、上下文、进度报告等） |
| `sideAskPendingDraft` | 输入栏入口暂存的草稿，面板读取后立即删除 |

## 隐私说明

- 上下文读取需 `messages` / `conversations` 授权，只在用户点击「读取上下文」或开启
  「携带会话上下文」并提问时发生；
- 不读取附件、图片、引用内容，不读取任何 API 密钥；
- 问答内容只存于插件私有存储，不写入宿主消息库；
- 请求复用当前 API 档案，**可能产生 API 费用**。

## 已知限制

- 通道非公开 API，宿主改动可能导致失效；
- 仅单轮问答（每次请求独立组装历史），不做工具调用与多轮 Agent 循环；
- 系统通知（可选，默认关）依赖 `system.notify` 写动作，宿主不支持或发送失败时面板会显示失败原因；进度报告本身只显示在面板里，不依赖系统通知；
- 上下文只覆盖焦点会话，不跨会话、不检索项目代码库。
