# snow-notify-hub

Snow App 客户端脚本：**回合结束通知中心** —— 多渠道推送 + 提示音 + 应用内提示。

## 功能

- **触发**：一轮 AI 回复结束。两条来源互补：
  - 当前打开的会话：`snow.on('stream-end')` 事件。
  - 其他会话（后台会话）：订阅元数据 `runtime` 域（live 推送），用宿主维护的 `completedConversationIds`（非焦点会话「已完成未读」集合）识别回合结束，因此切到别的会话后原会话跑完同样会提醒。
- 支持最短回合时长门槛与免打扰时段。
- **推送渠道（7 个）**：Server酱、PushPlus、Bark、钉钉、企业微信、Telegram、飞书。每个渠道可单独启停、填凭据、单独测试。
- **提示音**：21 种音效，全部由 Web Audio 实时合成（无外部音频文件），可调音量与试听。
- **应用内提示条**：右上角提示条，显示标题与正文（正文默认为会话名，可选回复摘要），配色跟随宿主主题。
- **设置浮层**：顶栏「待办列表」按钮旁的小铃铛按钮（点击在按钮旁弹出 tooltip 式浮层，展示全部配置项与渠道凭据）；也可从脚本菜单（`GM_registerMenuCommand` 的「通知推送设置」，居中弹窗）打开。配色跟随宿主主题。

## 安装

把 `snow-notify-hub.user.js` 装入 Snow App（插件 → 插件列表 → 脚本插件 → 导入文件），或在会话中让 AI 用 `config-set scope=userscripts` 安装。安装后在脚本菜单打开设置，填入推送渠道凭据并「测试推送」。

通过 AI 的 `config-set scope=userscripts` 更新脚本后会立即重新注入生效，无需重启应用。

## 后台会话提醒

宿主的 `stream-end` 事件按「当前会话的流式状态」派发，切走会话后原会话结束不会再触发，因此增加了基于元数据 `runtime` 域的监听：

- `runtime` 域是 live 域，运行时快照变化后约 200 ms 防抖推送，**无需 `@snow-privacy` 声明**。
- 主信号是 `conversation.completedConversationIds`（实测为字符串数组，不是文档描述的 Set）：宿主只在会话**正常跑完且不是当前打开的那个**时把 id 加进去，取消 / 中断不会加，语义精确。脚本只判「新增」——切到该会话时宿主会移除它，移除不代表新一轮完成。
- 兜底信号是 `streamingSessions[]`：某会话从流式集合消失也判定结束，用于覆盖被取消等未记入 `completedConversationIds` 的情况。两路信号由 30 秒去重兜住，不会重复提醒。
- 后台会话读不到界面文本，摘要改读 `messages` 元数据域（脚本已声明 `@snow-privacy messages`）；未声明、被拒或超时都会降级为「只提示会话标题」，不影响提醒本身。
- 去重：同一会话 30 秒内只提醒一次，`stream-end` 与后台监听命中同一次结束不会重复推送。
- 假 `stream-end` 有两道防线：① 结束的会话不是最近进入流式的那个（切走会话触发）直接忽略；② 没有对应 `stream-start` 的结束（`durMs === 0`，典型是「切回一个已完成的会话」）不提醒 —— 这是「点进通知又响一次」的根因。

## 渠道凭据

| 渠道 | 需要 |
| --- | --- |
| Server酱 | SendKey（`SCT…`） |
| PushPlus | Token |
| Bark | 设备 Key（可自定义服务器，默认 `https://api.day.app`） |
| 钉钉 | 机器人 Webhook 完整地址 |
| 企业微信 | 群机器人 Webhook 完整地址 |
| Telegram | Bot Token + Chat ID |
| 飞书 | 自定义机器人 Webhook 完整地址 |

凭据仅保存在本机插件存储（`GM_setValue`），不上传。HTTP 请求经应用网络栈发出，受系统代理设置影响。

## 边界（实测结论）

- **系统级通知不可用**：`GM_notification` 在当前 Snow App 构建（0.4.22）中静默失效（不弹出、`ondone` 也不触发），因此提示条改为应用内自绘。
- 提示音为合成音，非原始插件的内置音频文件；共 21 种预设。
- 「待确认」时机（工具授权等待）推送未实现：`runtime` 元数据域不含该状态字段；如需，可经宿主 Hooks 的 `toolConfirmation` 类型 + 外部脚本另行实现。
- 提示正文默认是**会话名**（来源：运行时快照 `streamingSessions[].title`，结束前一刻仍在快照里，因此无需额外声明 `conversations` 隐私域）；未命名会话取不到名字时正文为空。

## 配置项

| 项 | 默认 | 说明 |
| --- | --- | --- |
| 启用通知中心 | 开 | 总开关 |
| 最短回合时长 | 0 秒 | 低于该时长不通知；0 不限制 |
| 免打扰时段 | 关 | 开始/结束时间，支持跨零点 |
| 提示正文 | 会话名 | 会话名 / 回复摘要（摘要模式前台读 DOM、后台读 `messages` 元数据域） |
| 摘要字数 | 120 | 摘要最大长度；仅「回复摘要」模式生效 |
| 后台会话提醒 | 开 | 切到其他会话时，正在运行的会话回复完成也提醒 |
| 诊断日志 | 关 | 把运行轨迹写入本机存储，用于排查；排查完请关闭 |
| 显示提示条 / 停留时长 | 开 / 5 秒 | 应用内提示 |
| 启用提示音 / 音效 / 音量 | 开 / 清脆提示 / 0.5 | Web Audio 合成 |
